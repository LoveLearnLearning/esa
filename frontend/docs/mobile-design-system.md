# ESA 移动端设计系统与实现规范

本规范适用于 ESA 的 Flutter iOS、Android 与移动 Web 界面。目标是形成克制、专业、可长期高频使用的 AI 学习工作台，而不是营销页面。现有业务路由与数据逻辑优先保留，移动端通过响应式组件调整信息优先级。

## 1. 决策框架

新增或修改任何界面元素前，必须回答以下问题：

1. **目的**：它解决了什么任务？不能说明目的的装饰元素应删除。
2. **层级**：它是当前任务的主要操作、次要操作还是补充信息？同一页面只保留一个最强主操作。
3. **上下文**：它属于全局导航、模块导航、页面操作还是内容本身？避免重复标题和重复入口。
4. **可访问性**：是否具有明确语义、足够对比度、至少 44px 触控目标，并可适应系统文字缩放？
5. **性能**：是否引入不必要的重建、图片、监听器或布局动画？动画是否只使用低成本属性？

## 3. 色彩系统

实现来源：`lib/theme/esa_theme.dart`。

- 页面背景：`#080D14`
- 顶部与底部导航：`#0D1520`
- 内容表面：`#121C29`
- 悬浮或选中表面：`#18253A`
- 边框与分隔线：`#26364A`
- 主文字：`#F2F5F9`
- 次级文字：`#9AA8BA`
- 弱文字：`#66758A`

### 品牌蓝阶

- 50：`#EFF4FF`
- 100：`#DCE7FF`
- 300：`#91ACFF`
- 品牌主色：`#4F7FF7`（主操作）
- 600：`#3868DF`
- 700：`#2F55B7`

### 语义色

- 成功：`#4FAE83`

## 4. 字体与内容密度

- 正文：16px，行高 1.4–1.6。
- 辅助信息：至少 13px。
- 页面标题：20–24px；移动顶栏标题通常为 16–20px。
- 字重最多使用 Regular、Medium、Bold 三档。
- 长标题单行省略；内容型描述最多两行，禁止缩小到不可读字号。
- 输入框固定使用 16px，避免 iOS Web 聚焦时自动缩放。
- 所有关键页面必须验证 130% 系统文字缩放，不允许通过关闭文字缩放规避溢出。

## 5. 导航与信息架构

- 底部导航固定为“学习 / 研究 / 我的”，最多五项，并包含 iPhone safe area。
- “首页 / 作业 / 日程 / 知识 / 资料库”属于学习模块内部一级标签。
- 页面内部的筛选或视图切换使用紧凑二级标签，不使用高大的胶囊分段控件。
- 同一层级只显示一次标题。低频操作进入“更多”菜单。
- 首页采用 Chat-first：Composer 固定在底部导航上方，首次打开无需滚动即可输入。
- 键盘弹出时隐藏底部导航，Composer 跟随视口上移；滚动内容保留等量 bottom padding。

## 6. 移动组件库

共享实现：`lib/widgets/esa_mobile_controls.dart`。

### `EsaMobileIconButton`

- 固定 44×44px 触控区域，统一 20px Lucide 图标。
- 必须提供 Tooltip 与 Semantics label。
- 禁用态必须保留原因说明，例如“语音输入暂不可用”。
- 选中态使用品牌蓝与低对比选中表面，不使用发光或缩放动画。

### `EsaMobileTabStrip<T>`

- 支持横向滚动，避免在窄屏压缩标签文字。
- 使用底部 2px 指示线表达当前项。
- 每项具有按钮语义和 selected 状态。
- 标签切换立即更新，不附加阻塞动画。

### Chat Composer

- 左侧：附件；中间：1–4 行输入；右侧：语音与发送。
- 发送、停止、附件、语音均为至少 44×44px。
- 快捷建议视觉高度约 34px，但实际点击区域为 44px。
- 输入焦点在 100ms 内通过边框变化反馈。
- 发送后移动端收起键盘，将空间留给流式回答。

### 列表与内容行

- 整行点击，不重复放“进入”文字按钮。
- 单行最小触控高度 44px。
- 用分隔线组织相邻记录；避免每条记录独立套卡片。
- 加载使用骨架或进度指示；空状态保持紧凑，并给出可执行恢复操作。

## 7. 微交互规则

每个交互需要定义触发、规则、反馈、循环和模式：

- **触发**：点击、输入、拖动、系统键盘或网络状态变化。
- **规则**：只更新当前任务所需状态，不产生意外导航或重复请求。
- **反馈**：按压水波纹、焦点边框、加载指示、成功或错误说明应立即出现。
- **循环**：持续加载和重试必须可终止；禁止无限无反馈等待。
- **模式**：选中、编辑、加载、禁用和错误状态必须视觉与语义一致。

标准动画为 140–180ms，曲线使用 `easeOutCubic`。优先使用 opacity 与 transform，避免反复改变复杂布局属性。所有动画通过 `EsaMobile.motion(context)` 响应系统 Reduce Motion；关闭动画后状态变化仍必须清晰。

## 8. 可访问性检查

- [ ] 所有操作目标至少 44×44px，主要操作位于拇指易达区域。
- [ ] 图标按钮具有 Tooltip、Semantics label 和 enabled/selected 状态。
- [ ] 正文对比度至少 4.5:1，非文本关键图形至少 3:1。
- [ ] 不仅依靠颜色区分状态。
- [ ] 支持屏幕阅读器的阅读顺序与可操作名称。
- [ ] 支持键盘、方向键、Tab、Enter 与平台常用组合键，不拦截无关按键。
- [ ] 支持 130% 文字缩放，无截断、重叠或不可达内容。
- [ ] 错误信息说明原因和下一步，不只显示“失败”。
- [ ] 无强制倒计时；破坏性操作提供确认或可恢复机制。

## 9. 性能实现

- 使用 `const` Widget、局部 `ListenableBuilder` 和稳定 Key，缩小重建范围。
- 长列表使用惰性 builder，不一次性创建全部子项。
- 图片优先使用 WebP/AVIF（平台支持时），提供目标尺寸并启用懒加载。
- 页面销毁时释放 `TextEditingController`、`FocusNode`、`ScrollController` 和监听器。
- 避免在 build 中发起网络请求；使用状态层缓存与去重。
- 动画只改变 transform/opacity 或小范围容器，并尊重 Reduce Motion。
- 乐观更新必须具有失败回滚与明确错误状态。

## 10. 平台差异

- **iOS**：遵循底部安全区；正文输入 16px；键盘出现时 Composer 使用可视区域高度；重要确认可使用轻量触感反馈。
- **Android**：触控目标建议提升到 48px；处理返回手势和系统导航栏 Insets；按压反馈使用 Material ripple。
- **移动 Web/PWA**：兼容浏览器动态地址栏与 `visualViewport`；保留键盘焦点与无障碍焦点轮廓；不拦截浏览器和编辑器常用快捷键。

## 11. 验证方法

每次移动端结构变更至少完成：

1. `flutter analyze`
2. 相关 Widget 测试和全量非视觉测试
3. 390×844 与 430×932 首页 Golden 截图
4. 430×932、130% 文字缩放布局测试
5. 300px 模拟键盘 Insets 测试
6. 日程今日/3 日/周视图与研究项目列表截图
7. 检查首屏 Composer、最后一条内容、safe area、横向溢出和触控尺寸
8. `git diff --check`

发布前还需在真实 iPhone Safari、Android Chrome 与至少一台原生设备上检查键盘、触感、滚动和系统字体缩放。
