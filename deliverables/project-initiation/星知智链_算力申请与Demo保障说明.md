# 星知智链代码架构和算力申请计划

## 一、代码框架

### 1.1 整体框架

星知智链由 Flutter Web 前端、FastAPI 后端、Agent Runtime、模型服务和知识库服务组成。系统面向学习、教学和科研三个场景，通过统一的 Agent Runtime 调用相应工具，完成问答、作业分析、学情管理、科研资料处理等任务。

### 1.2 模块结构

```text
esa/
├── frontend/                  Flutter Web 前端
├── backend/
│   ├── agent/                  Agent、工具和运行时编排
│   ├── core/web/               FastAPI、SSE 和业务接口
│   ├── core/services/          教学分析、科研写作等服务
│   ├── core/utils/config.py    模型、LoRA、RAG 配置
│   └── scripts/dataset/        训练数据生成、校验和切分
└── deploy/
    ├── rag/                    RAG 和知识库部署配置
    └── nginx/                  前后端反向代理配置
```

主要业务结构为：

```text
用户登录
→ Agent Runtime 理解任务并选择工具
→ 后端执行业务操作
→ 模型生成回答或分析结果
→ SSE 返回前端
→ 必要时写入作业反馈、学习证据或科研文档
```

### 1.3 部署结构

本次申请使用一台配备 8 张 A800 80GB GPU 的服务器，按当前部署配置分配如下：

| GPU | 服务 |
|---|---|
| GPU 0–5 | Qwen3.5-122B-A10B 主模型，TP=2、PP=3 |
| GPU 6 | Qwen3.5-9B 辅助模型 |
| GPU 7 | Embedding、Reranker 和 MinerU 文档处理 |

Qdrant、ESA 后端等服务在同一台机器上运行。微调验证和 Demo 运行分时进行，不要求训练和完整 Demo 服务同时运行。

## 二、微调验证与 Demo 计划

### 2.1 验证内容

本阶段只做比赛 Demo 所需的短周期微调验证和系统联调，不开展额外的论文实验。主要内容为：

1. 生成、校验和切分 Agent 工具调用训练数据。
2. 在外部训练环境完成一轮 LoRA/SFT 微调验证。
3. 检查 LoRA 适配器能否被主模型 vLLM 正常加载。
4. 启动完整运行栈，验证学习、教学和科研 Demo 流程。
5. 完成预演并录制比赛 Demo 视频。

### 2.2 资源与时间预算

| 项目 | GPU 资源 | 预计时间 | GPU-hours |
|---|---:|---:|---:|
| LoRA/SFT 微调验证 | 8 张 A800 | 12 小时 | 96 |
| 适配器加载和完整系统启动 | 8 张 A800 | 4 小时 | 32 |
| Demo 流程预演 | 8 张 A800 | 3 小时 | 24 |
| Demo 录制和必要重录 | 8 张 A800 | 5 小时 | 40 |
| **合计** | **8 张 A800** | **24 小时** | **192** |

GPU-hours 按“GPU 数量 × 使用小时数”计算。本次申请预计使用 **8 张 A800、24 小时，共 192 GPU-hours**。

### 2.3 执行顺序

```text
训练数据准备
→ LoRA/SFT 微调验证
→ 适配器加载检查
→ 启动完整运行栈
→ 教学研 Demo 预演
→ 正式录制
```

本次申请只覆盖微调验证和比赛 Demo 录制。若进入评审阶段，评审平台持续运行所需算力另行申请。
