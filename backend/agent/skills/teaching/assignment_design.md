# 作业设计

## 1. 触发条件
用户请求设计作业、练习题、测试题或评估任务时触发。

## 2. 任务澄清
1. **作业类型**：练习/测试/项目/报告/实验
2. **教学目标**：知识掌握/技能训练/能力培养/素养提升
3. **难度要求**：基础/中等/挑战/综合
4. **时间限制**：课堂完成/课后作业/周末作业/长期项目

## 3. 设计框架
### 3.1 目标对齐
- **课程标准**：对齐课程标准和教学大纲
- **学习目标**：明确具体的可测量目标
- **知识维度**：事实/概念/程序/元认知
- **认知层次**：记忆/理解/应用/分析/评价/创造

### 3.2 难度控制
- **基础题**：概念记忆、简单应用（60-70%）
- **中等题**：综合应用、分析问题（20-30%）
- **挑战题**：创新思维、复杂问题（10%）
- **梯度设计**：由易到难，循序渐进

### 3.3 题型设计
- **选择题**：概念辨析、知识判断
- **填空题**：关键术语、公式应用
- **解答题**：问题解决、推理证明
- **论述题**：观点阐述、综合分析
- **实践题**：实验设计、项目实施

### 3.4 评价规则
- **评分标准**：明确各题分值和评分细则
- **反馈要求**：提供具体、建设性的反馈
- **改进建议**：针对常见错误的改进指导

## 4. 执行流程
1. 调用 `get_teaching_context` 获取教学上下文
2. 调用 `retrieve_knowledge` 检索相关教学资源
3. 分析教学目标和学生特点
4. 设计作业结构和题目
5. 制定评价规则和反馈要求

## 5. 输出规范
```text
【作业概览】
类型：[作业类型]
目标：[教学目标]
难度：[难度分布]
时间：[预计完成时间]

【题目设计】
[详细题目列表，包括题型、分值、考查点]

【评价规则】
评分标准：[详细评分标准]
反馈要求：[反馈内容和格式]
改进建议：[针对常见错误的改进建议]

【教学建议】
布置时机：[建议布置时间]
讲解重点：[需要重点讲解的内容]
后续衔接：[与后续教学的衔接]
```

## 6. 质量标准
1. **有效性**：题目能有效测量学习目标
2. **公平性**：题目无歧义，对所有学生公平
3. **可行性**：学生能在规定时间内完成
4. **诊断性**：能识别学生的学习问题

## 7. 禁止事项
- 不得设计超纲题目
- 不得设置歧义或陷阱题
- 不得忽略评价规则的明确性
- 不得抄袭已有作业题目
- 不得跳过教学目标分析
- 不得设计无法评分的题目
