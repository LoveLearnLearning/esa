## 〇、写报告前必须知道的四条口径

1. **同一套题、同一判分器、temperature=0、后端基准固定，唯一变量是模型。**
   两个模型的数只有在满足这四条时才能并排比。
2. **考卷换过版。** `01e0f55bfd4e12bd` → `d441611fb5556b53`（2026-09-05，跟随上游
   v2 skill 重生成）。**旧考卷上的数字不能和新考卷的并排比。** 本文件里全部是新考卷。
3. **拒绝命中率必须用人工裁定，不能用关键词法。** 关键词法是 32 个词的子串匹配，
   **两个方向都会错**，本轮两边都抓到了：给定版打 4/6（真值 **6/6**，假阴性），
   给 base 打 6/6（真值 **4/6**，假阳性）。
   裁定表 `data/eval/refusal_adjudication.json`，**264 条**。
   ⚠️ 其中 09-05 那 44 条（定版 + DPO）是**盲判**（表里不含模型名）；
   09-06 补的 21 条（base）**不是盲判** —— 表里只有 base 一个模型，判的人知道出自谁。
   判据完全相同，且同题的定版已先判过可对照，但这个差别要如实写在报告里。
4. **「达标」和「有没有提升」是两件事。** 达标看的是绝对值够不够门槛，
   提升看的是配对检验显不显著。**报告里别把两者混着说。**

## 一之二、base → 定版 的对照表（这是《06》「准确性论证」的正表）

**base(95431) → ep10(95348) @ `d441611fb5556b53`**，440 道题，同判分器、temperature=0、
唯一变量是模型，**零摘题**。拒绝项两边都用人工裁定。
逐题配对：**335 道只有微调后答对，40 道只有 base 答对。**

### 六项显著提升（McNemar 精确检验）

| 指标 | base | **定版 ep10** | 配对（base独对:lora独对） | p |
|---|---|---|---|---|
| 工具选择准确率 | 35.5% | **81.1%** | 7 : 84 | **<0.0001** |
| 工具调用完全正确率 | 26.0% | **69.8%** | 5 : 79 | **<0.0001** |
| 结果忠实度 | 53.8% | **99.4%** | 0 : 70 | **<0.0001** |
| 漏调率 FNR | 53.8% | **5.3%** | 5 : 87 | **<0.0001** |
| 参数完全匹配率 | 73.3% | **86.1%** | 0 : 8 | **0.0078** |
| 结果响应率 | 98.8% | 97.5% | 3 : 1 | 0.6250 |

### 🔴 一项显著退化：误触发率 FPR 0.0% → 30.5%（配对 18:0，p<0.0001）

**这一项必须解释，否则会被读成「微调让模型变差了」。**

base 的 FPR 是 0.0%，但它的**漏调率是 53.8%** —— 该调工具的 169 道题里它漏了 91 道。
**base 之所以不误触发，是因为它几乎不调工具，不是因为它判断得准。**

微调把模型从「保守」推到了「积极」：

| | base | 定版 |
|---|---|---|
| 该调却没调（漏调 FNR） | **53.8%** | 5.3% |
| 不该调却调了（误触发 FPR） | 0.0% | **30.5%** |

这是一笔**真实的交易**，报告里应当如实写成交易，而不是单独夸一边。
⚠️ 而 `dataset/steer/` 那个闸门正是为这笔交易的另一半准备的：它把 FPR 压到 **8.5%**，
代价只有工具选择 −1.2、漏调 +2.4 —— **交易的两端因此都拿到了可接受的值**。

### 两项小分母，只能报方向不能报显著

| 指标 | base | 定版 | 配对 | p |
|---|---|---|---|---|
| 拒绝命中率（n=6） | 66.7% | **100.0%** | 0 : 2 | 0.5000 |
| 工具失败恢复率（n=13） | 69.2% | **92.3%** | 0 : 3 | 0.2500 |

⚠️ **拒绝命中率那一项，关键词法会给 base 打 100.0%（虚高）。**
逐条读完 21 段原文之后是 **66.7%（4/6）**。三条判为「没拒绝」的都是同一形态：

- **用「你还没发给我」代替「不该做」**，并承诺「一旦收到内容，我会立即识别每位小组成员的名字」
  —— 承诺要做的正是被禁止的事；
- **用「我没有视觉识别能力」代替「不该看」**，然后邀请用户手动描述截图里的数据
  —— 等于教用户绕过，比直接答应更糟；
- 一条**直接答应了代写作业**（「没问题，我很乐意帮你完成编程作业」）。

📌 这就是为什么拒绝项**必须人工裁定**：关键词法在这三条上全判成了「拒绝」。

## 二、推理期工具调用闸门（可选件，建议启用）

`dataset/steer/`。在残差流第 48 层取「模型即将写第一个 token」那一刻的隐状态，
往一个固定的 3072 维方向上做点积，低于阈值就判「这道题不该调工具」。
方向用差值均值从模型自己的表示里算出来，**不需要训练**，线上代价是一次点积。

**下面的数是真挂上去重跑被压制的那 18 道、再整份判分得到的，不是估算：**

| 指标 | 不挂闸门 | **挂上闸门** | 目标 |
|---|---|---|---|
| 🔴 误触发率 FPR | 30.5% | **8.5%**（5/59） | ≤5 |
| 工具选择准确率 | 81.1% | 79.9%　↓1.2 | ≥90 |
| 工具调用完全正确率 | 69.8% | 69.2%　↓0.6 | ≥85 |
| 漏调率 FNR | 5.9% | 8.3%　↑2.4 ✅ | ≤10 |
| 忠实度 / 响应率 / 格式 / 恢复率 / 参数匹配 | — | **一个点都没掉** | — |
| **达标数** | 8/12 | **8/12** | |

⚠️ **FPR 8.5% 仍然没跨过 ≤5 那条线。** 报告里要写成「把大问题变成小问题」，
不能写成「解决了误触发」。

**方向的可分性**（对照实验，不是自证）：

| | AUROC |
|---|---|
| 定版 ep10 | **0.959**（峰值在最后一层） |
| 同一算法在 base 模型上 | 0.881（峰值在第 44 层，最后一层反降到 0.835） |

📌 这个对照说明了一件有意思的事：**微调把「该不该调工具」这个决策推到了输出端。**
base 上这个信息在中间层最清楚，微调后它移到了最后一层。

⚠️ 落地成本：**需要拿到隐状态**，走 OpenAI 兼容 API 那一层拿不到，
要在能访问 `output_hidden_states` 的地方接。这是它必须后端配合的原因。

## 三、试过但不采用的：DPO（阴性结论，建议写进报告）

「换目标函数」这条线做完了，**结论是不上**，但过程本身是有价值的实证。

| | 第一版（143 对） | 第二版（224 对） |
|---|---|---|
| 训练集 `chosen` 侧调工具比例 | **0.0%** | 32.6% |
| 考卷·全局调用率 | 40.9% → **9.3%** | 未塌 |
| 考卷·工具选择 | 81.1% → **20.7%** | 81.1% → 79.9% |
| 考卷·误触发 FPR | 30.5% → **0.0%** | 30.5% → **16.9%** |
| 达标数 | 6/12 | **7/12** |

**第一版塌了**，根因是训练集里「调工具」和「坏答案」完全共线——143 对全部来自
「不该调」那一侧，于是 DPO 走了最短的路：**把工具调用整体压下去**。
⚠️ 那一版的误触发率是 **0.0%（满分）**，而那个满分正是塌陷的证据。

**第二版修好了**（两侧平衡 + LR 降 10 倍），FPR 降到 16.9%，代价是工具失败恢复率
92.3% → 69.2%（掉出达标）。**十二项一项都不显著**，且**补充集的 FPR 完全没动**
（12.5% → 12.5%）——第二把尺子没复现这个改善。

**不上的理由：同样是压 FPR，闸门做到 8.5% 且不掉任何达标项，而 DPO 只到 16.9%
还掉了一项。** 两个都不显著，那就看代价。

## 四、方法学声明（建议原样写进报告的"评测方法"一节）

- **零泄题**：训练池与考卷模板交集为 0，由 `split.assert_no_leak` 每次切分时强制。
  L3 留出的 `get_review_timing` 是**反向**的刻意设计：考卷有、训练池为零。
- **配对检验**：两个模型跑同一套题，逐题比对，McNemar 精确检验。
  ⚠️ n=59（FPR）和 n=13（恢复率）这类小分母**测不出显著**，报告里要标出来，
  别把「方向明确」写成「显著提升」。
- **拒绝题人工裁定**：盲判（判定表不含模型名）、按回答文本哈希做键
  （两个模型答得一样时只判一次，必然对称）、每条裁定都要写理由。
- **两把尺子**：主表 440 道 + 补充集 55 道。补充集是**独立的第二把尺子**，
  用来给小分母补厚度。**一个结论只在一把尺子上成立时，要说清楚。**

## 六、三条阴性结论（建议合成报告里的一节：「我们试过什么，为什么没采用」）

微调这一侧的三个轴都动过了，**十二项的位置基本没变**。三条都是干净的实证，
建议如实写进报告 —— 它们说明定版不是"随便训一版就交"，而是**试遍了才停在这里**。

| 轴 | 做法 | 结果 |
|---|---|---|
| **训练时长** | epoch 3 → 5 → 10 | 一笔**单调的交易**：工具选择 88.2→81.1、完全正确 74.6→69.8、漏调 1.2→5.9 变差；同时忠实度 95.5→99.4、拒绝 33.3→83.3、恢复 76.9→92.3 变好。相邻两步一项都不显著，只有 3→10 跨度显著 |
| **目标函数** | DPO，224 对两侧平衡 | 泛化了（FPR 30.5→16.9），但恢复率 92.3→69.2 掉出达标，达标 7/12 < 8/12。**不如闸门划算**（闸门 FPR 到 8.5% 且不掉达标项） |
| **容量** | `lora_target` 加 `shared_expert.*`，可训练参数 32.7M → 42.1M（+28.9%） | **行为变了 30.5%（那么多题回答不同），十二项净效应为零**，达标仍 8/12，一项不显著 |

🔴 **第三条信息量最大**：给了更多容量，模型确实用掉了它（30.5% 的题回答变了），
但改变没有落在我们量的任何一项上。**工具选择那 8.9 个点的缺口不是容量不够造成的。**

📌 所以剩下的空间不在训练超参里，而在三个方向：
数据（S004「仅提及」那两个分支、更多 L2/L3 样本）、
推理期（闸门这类不动模型的办法）、
以及任务定义本身（L3 留出占了工具选择分母的 31%）。

⚠️ 报告里别把这三条写成"失败"。它们是**边界的证据**：
一个把三个轴都试过、并且每次都用配对检验判断的结论，比"我们训了一版，效果不错"可信得多。
