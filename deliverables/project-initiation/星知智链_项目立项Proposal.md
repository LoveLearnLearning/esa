# 星知智链（ESA）项目立项 Proposal

## 面向一流学科建设的计算机学科垂类大模型与教学研一体化创新应用

**项目名称：** 星知智链（Efficient Study Agent，ESA）  
**申报方向：** XH-202620“面向一流学科建设的学科垂类大模型与创新应用开发”  
**聚焦学科：** 计算机学科  
**文档用途：** 指导教师审稿、项目正式立项  
**版本日期：** 2026 年 9 月 10 日

## 一、项目摘要

星知智链不是一个面向所有问题的通用聊天机器人，而是面向计算机学科建设的可信教学研智能体平台。项目关注的核心问题是：高校已经积累了课程、作业、学习行为、科研文献和实验数据，但这些信息分散在不同系统中，尚未被组织成能够持续支持学生成长、教师决策和科研推进的可信证据。

项目以计算机课程知识图谱为学科结构，以检索增强生成为知识依据，以 Student Model 为学生状态表示，以受控智能体工作流连接任务执行，构建学习、教学和科研三个相互隔离又可在授权下协同的工作空间。学生侧根据真实学习证据调整讲解深度、前置知识补偿和复习建议；教师侧完成建班、作业发布、AI 辅助分析、人工复核、反馈发布和班级诊断；科研侧围绕具体项目完成前沿追踪、资料组织、版本化写作与数据分析。

项目要解决的不是“大模型能不能回答问题”，而是“大模型的回答能否有依据、能否适合具体学生、能否进入教师可控的教学流程、能否沉淀为后续可使用的学科证据”。最终产出包括一套可运行的软件平台、一套计算机学科知识资产、一套证据驱动的个性化学习模型、两类教学与科研工作流、一套垂类模型适配与评测方法，以及可供后续课程试点使用的工程和验证材料。

## 二、Motivation：为什么要做这个项目

### 2.1 表层问题：教学、学习和科研工具彼此割裂

当前高校的数字化系统通常按职能建设：教务系统负责课程与成绩，学习平台负责资料与作业，通用大模型负责问答，文献工具负责检索，数据工具负责分析。这些系统分别解决了局部问题，却没有形成贯穿教学研全过程的连续支持。

这种割裂在计算机学科中尤其明显：

1. **学生得到回答，却没有形成持续的学习状态。** 同一个问题可以被回答很多次，但系统通常不知道学生是否独立完成、使用了几级提示、错误来自哪个前置知识点，也无法据此决定下一次应该补基础、做迁移题还是安排复习。
2. **教师掌握结果，却难以获得可行动的诊断。** 教师能够看到作业分数，但开放题和代码文本题的错因归类、知识点聚合、连续薄弱识别与个别学生跟进仍需要大量人工整理。
3. **科研工具提高了单步生成效率，却没有覆盖完整项目流程。** 文献检索、资料整理、写作和数据分析分散在不同工具中，模型容易脱离项目材料生成内容，也容易把统计相关性、热点词频或语言润色包装成未经验证的科研结论。
4. **教学、学习和科研之间缺少受控的知识循环。** 科研前沿难以及时转化为课程资源，教学中发现的共性问题难以沉淀为学科建设素材，学生的学习证据也无法在保护隐私的前提下支持教学改进。

### 2.2 深层问题：信息没有转化为可信、可执行的证据

上述现象背后的共同矛盾不是信息不足，而是缺少一条从真实任务到可靠证据、再从证据到下一步行动的闭环。

通用大模型擅长生成自然语言，但一次回答本身不能证明学生已经掌握，也不能自动成为教师的正式评分，更不能替代研究者对来源、方法和结论的判断。因此，项目将“证据”而不是“生成文本”作为系统的核心对象：

- 学生只有在完成真实且可评价的作答、练习、复述或迁移任务后，系统才更新学习状态；
- AI 批改只作为结构化建议，教师复核并发布后才能成为正式教学反馈；
- 科研写作只能基于已授权材料，缺少来源时必须标记待补，不能虚构论文、数据或结论；
- 每一次工具调用和业务写入都受身份、工作空间和具体资源约束。

因此，本项目的 Motivation 可以概括为：**把一次性的 AI 问答升级为围绕计算机学科知识结构、真实任务和人工责任形成的教学研证据闭环。**

## 三、为什么这个问题值得关注

### 3.1 对学生：个性化不能只表现为“换一种说法”

真正的因材施教至少需要回答四个问题：学生当前在哪个知识点上遇到困难、问题是否来自前置知识、学生的成功是否依赖提示、下一步学习行动是什么。计算机课程具有显式知识依赖，例如递归影响树的遍历，指针影响链表，图结构影响最短路径，进程同步影响死锁分析。若系统忽略这些依赖，只根据一轮对话生成答案，所谓个性化往往只是在语言难度和篇幅上做表面调整。

ESA 将正确性、提示级别、尝试次数、独立性、回忆、解释和迁移表现共同作为学习证据，区分长期掌握度与随时间变化的保持率，并利用前置关系决定是否先补基础。这样，个性化才从“生成风格差异”转化为“教学策略和学习路径差异”。

### 3.2 对教师：大班教学需要扩大诊断能力，而不是转移责任

开放题、简答题和代码文本题能够反映学生思维过程，但批改和归因成本高。若完全由 AI 自动决定分数，会引入错误评分、不可解释判断和责任归属问题；若完全依赖人工，又难以在大班环境中持续开展细粒度诊断。

本项目采用“AI 初步分析—教师逐题复核—教师主动发布”的人机协同模式。AI 承担重复性的信息整理和候选判断，教师保留对分数、错因、知识点和反馈的最终裁决权。正式反馈发布后，系统再聚合班级薄弱知识点、关注学生和可能的前置根因，帮助教师从重复阅卷转向关键判断与教学干预。

### 3.3 对科研：效率提升必须与科研诚信同时成立

科研场景对错误来源、虚构引用和过度解释的容忍度极低。一个能够快速生成文本但不能说明材料边界、数据来源和分析方法的系统，可能提高表面效率，却增加核查成本与学术风险。

ESA 将科研活动绑定到具体项目，支持基于 arXiv 结果的前沿追踪、项目文档的版本化写作以及 CSV、JSON、TXT 数据的描述统计、相关分析、分组比较和文本频次分析。系统明确区分“筛查信号”和“研究结论”，并要求写作只使用用户提供的事实与材料，使 AI 成为研究过程中的受控协作者，而不是自动产出结论的替代者。

### 3.4 对一流学科建设：需要可积累的学科能力底座

一流学科建设不仅需要单个教师或学生更高效，还需要形成可持续积累的课程知识结构、资源标准、学习证据、教学反馈和科研方法资产。项目将课程、知识点、前置关系、知识来源、标准答案、检索标注、作业反馈和研究项目统一纳入可追溯的数据结构，为后续课程迭代、教学研究和跨课程推广提供底座。

## 四、为什么过去难以系统实现

这里不宜简单表述为“此前完全没有人做过”。智能教学系统、学习管理系统、知识追踪、教育知识图谱和科研助手都已有长期研究。真正尚未被普遍解决的是：**如何把这些能力整合成一个既能连续工作、又能保证证据、权限和责任边界的学科级系统。**

| 既有方案 | 已解决的问题 | 仍然存在的缺口 |
|---|---|---|
| 学习管理系统 | 课程、资料、作业和成绩管理 | 能记录流程，但对开放题语义、错因和个体学习策略的理解有限 |
| 通用大模型 | 自然语言问答、解释和内容生成 | 缺少稳定学科结构、长期学生状态、来源约束和业务权限，容易产生幻觉 |
| 传统智能导师系统 | 领域模型、学生模型和教学策略 | 通常覆盖较窄题型和固定交互，构建成本高，难以处理开放问题和多模态资料 |
| 自动批改系统 | 降低部分题型的批改成本 | 容易把模型判断直接等同于正式成绩，难以形成教师可控的证据回流 |
| 文献或写作助手 | 检索、摘要、润色等单项任务 | 与具体研究项目、数据和版本历史脱节，缺少完整流程及科研诚信边界 |

过去难以形成完整方案，主要有五个工程与理论原因：

1. **跨任务语义理解能力不足。** 传统规则系统难以统一处理问答、作业文本、代码解释、科研材料和多轮更正。
2. **学科建模成本高。** 课程知识点、前置关系、来源和评价标准需要长期整理，不能只靠模型临时生成。
3. **学习状态不可直接观测。** 一次答对不等于掌握，必须综合任务质量、提示、独立性和时间因素，避免把模型猜测写入学生档案。
4. **高风险写操作需要责任边界。** 成绩、学生画像、科研结论和项目数据不能由模型在无授权、无复核条件下修改。
5. **部署成本和复现难度高。** 大模型、向量检索、文档解析、流式交互和多端客户端需要同时稳定运行，过去很难在有限资源下完成学科级集成。

## 五、什么技术和理论更新使项目现在可行

本项目的可行性不是来自某一个孤立突破，而是以下技术与理论在近年形成了可组合的工程窗口。

### 5.1 具备工具调用能力的大模型

大模型已经从单纯文本生成器发展为能够理解自然语言任务、补充缺失参数、选择工具并依据工具结果继续回答的 Agent 核心。ESA 将计算、检索、学习状态、附件解析和科研工作流注册为结构化能力，使模型负责意图理解和任务编排，确定性服务负责计算、查询和写入。

### 5.2 LoRA 与 SFT 降低垂类适配成本

参数高效微调使团队无需重新训练完整基座模型，即可针对工具选择、参数生成、错误恢复和结果忠实度进行行为适配。项目已形成从真实 Tool Schema、场景模板、程序化数据、人工裁定到固定考卷评测的训练闭环，为垂类模型的可复现优化提供基础。

### 5.3 RAG、DocIR 与知识图谱共同提供学科约束

RAG 解决“回答依据从哪里来”，知识图谱解决“知识之间如何关联”，DocIR 解决“PDF、Word、PPT、表格和图片如何转化为统一、可定位的证据”。三者结合后，系统既能检索原始材料，又能利用课程和前置关系组织学习与诊断，而不是只做相似文本召回。

### 5.4 Student Model 将学习科学转化为运行时策略

项目吸收智能导师系统、掌握学习、知识追踪、间隔重复和认知负荷管理的思想，但不把论文中的参数直接照搬为结论。当前 Student Model 将掌握度与保持率分离，按证据质量渐进更新状态，并把状态映射为基础、标准和进阶三档讲解深度。未知状态保持未知，不被武断地解释为薄弱。

### 5.5 人在回路与能力作用域使高风险应用可治理

模型能力提升并不自动意味着可以获得更多权限。ESA 使用学习、教学、科研三类 Workspace，结合用户角色、班级、作业、科研项目和附件绑定，在每轮对话前编译允许使用的工具视图。教学反馈必须由教师发布，科研动作可要求用户审批，审计信息与模型可见信息分离。这使系统能够在保持自然交互的同时，对写操作和敏感资源保持最小必要访问。

## 六、项目总体方案

项目采用“一套可信底座、三个工作空间、两类证据闭环”的总体设计。

```text
                         计算机学科知识底座
          课程—知识点—前置关系—来源—题目—检索证据
                                  │
             ┌────────────────────┼────────────────────┐
             │                    │                    │
          学习空间             教学空间             科研空间
     问答/练习/知识地图    班级/作业/复核/看板   项目/前沿/写作/数据
             │                    │                    │
             └──── 学习证据闭环 ──┘      科研证据与版本闭环 ──┘
                                  │
                 角色、资源、审批、审计与来源治理
```

### 6.1 “贯穿教学研”的准确含义

项目所说的“贯穿”不是把学生私人数据、教师班级数据和科研项目数据无条件打通，而是在同一学科底座和治理框架下形成受控协同：

1. **教学与学习形成直接闭环。** 教师发布带知识点标签的任务，学生提交形成真实表现，教师发布的正式反馈回流个人学习状态，学生再获得针对性讲解和练习，班级看板同时聚合共性问题。
2. **科研为学科知识更新提供受控通道。** 科研空间追踪前沿、整理材料并保留来源；研究成果只有经过教师或研究者确认、完成来源登记后，才适合转化为课程资源。该自动发布通道属于后续建设内容，当前不允许模型直接把科研生成内容写入公共课程知识库。
3. **学习向科研能力培养延伸。** 学生可在科研项目空间中使用文献、写作和数据分析能力，但个人掌握度只用于调整学习支持，不自动成为科研评价或人员筛选依据。
4. **三类场景共享技术规范而不共享越权数据。** 它们共享身份体系、知识来源规范、Agent Runtime、工具协议和审计方法，具体业务资源仍按班级、作业和项目隔离。

### 6.2 学生侧：如何真正做到因材施教

学生侧不是根据用户自我描述简单贴标签，而是依赖可评价行为形成动态状态：

- 将自然语言问题解析到已知课程知识点，无法解析的知识点拒绝写入；
- 根据答题正确性、提示级别、尝试次数、独立性、解释和迁移表现评估证据质量；
- 分离长期掌握度与当前保持率，支持“会但需要复习”和“尚未掌握”的差异化处理；
- 识别薄弱前置知识，必要时先补前置再返回当前问题；
- 按状态选择基础、标准或进阶讲解深度；
- 将知识地图、复习队列、掌握度报告和练习推荐转化为具体下一步行动。

### 6.3 教师侧：如何更全面地管理班级

教师侧围绕真实教学工作流组织功能：

```text
创建班级并邀请学生
→ 创建并发布带知识点标签的作业
→ 学生提交
→ AI 生成逐题结构化分析建议
→ 教师修改分数、错因、评语和知识点
→ 教师主动发布正式反馈
→ 反馈写入学生学习证据
→ 班级看板聚合薄弱知识点、关注学生和前置根因
```

教师看到的不是单一平均分，而是提交进度、知识点得分率、薄弱人数、连续薄弱提醒、学生在本班形成的正式证据以及可能的前置根因。教师无法读取学生私人对话、个人记忆和无关科研项目，从而在扩大观察范围的同时维持合理的数据边界。

### 6.4 科研侧：如何辅助科研全流程

科研空间以“项目”为最小资源边界，当前规划覆盖：

- **项目管理：** 项目创建、归档、项目说明和项目级智能体指令；
- **前沿追踪：** 同时按时间和相关性检索 arXiv，去重后生成年度分布、热点词和增长信号；
- **资料与写作：** 创建研究文档并保留版本，支持大纲、文献综述、润色和格式检查；
- **数据分析：** 上传 CSV、JSON、TXT，完成数据概览、描述统计、相关分析、分组比较和文本频次分析；
- **可信边界：** 写作只使用用户提供材料，缺少来源时标记待补；相关系数不得被解释为因果；高风险动作重新校验项目和数据归属。

后续将补充可视化、统计检验、代码/公式执行验证以及研究输出向课程资源转化的人工审核流程，但不以“自动完成科研”作为项目目标。

## 八、项目创新点

### 8.1 从“回答中心”转向“证据中心”

系统不把生成一段看似正确的答案视为任务结束，而是继续判断证据是否真实、是否有来源、是否能够进入学生状态或业务流程，以及下一步应该由谁确认。

### 8.2 将学科知识结构同时用于助学和助教

知识图谱不仅用于学生选课和知识地图，也用于作业标签、班级薄弱点聚合和前置根因分析，使同一知识结构贯穿个体学习与班级教学。

### 8.3 用教师最终裁决解决“自动批改”责任问题

AI 只提供建议，正式分数、错因和反馈由教师确认后发布。该设计既保留 AI 的效率优势，又避免模型在未经审核时改变学生档案。

### 8.4 用资源作用域而不是提示词承诺权限

班级、作业、科研项目和附件是否可见，由服务端授权结果决定；模型无法通过自然语言声称“已获得授权”来扩大访问范围。

### 8.5 将垂类模型训练变成可复现的行为工程

项目不只展示训练损失，而是围绕工具选择、参数匹配、错误恢复、结果忠实度、误触发和漏调建立固定考卷、人工裁定和配对评测，能够解释模型改进与退化分别发生在哪里。

## 九、拟研究问题与验证方法

| 研究问题 | 核心假设 | 验证方法 | 主要指标 |
|---|---|---|---|
| RQ1：证据驱动的 Student Model 能否形成稳定个性化？ | 同一知识点不同证据质量会触发不同状态与教学策略 | 构造多类学习轨迹并开展学生试用 | 策略一致性、推荐解释可理解性、下一次独立作答表现 |
| RQ2：AI 建议加教师复核能否改善主观题处理流程？ | AI 可减少信息整理工作，但最终质量依赖教师裁决 | 教师完成同类作业的人工流程与辅助流程对比 | 单份处理时间、AI 建议修改率、评分一致性、反馈完整度 |
| RQ3：知识图谱能否提升薄弱点解释能力？ | 前置关系能够将表面错误关联到可干预的基础问题 | 选择具有明确依赖链的课程任务开展案例分析 | 知识点识别准确率、前置根因命中率、教师认可度 |
| RQ4：受约束科研工作流能否在不牺牲诚信的前提下提效？ | 项目绑定、来源限制和方法说明能降低无依据生成 | 对前沿追踪、写作和数据分析进行人工对照 | 任务耗时、来源核验通过率、人工修改率、虚构项数量 |
| RQ5：LoRA 能否提升 Agent 的工具行为？ | 参数高效微调可改善工具选择和结果忠实度 | 同一固定考卷对基座与微调模型逐题配对 | 工具选择、完整调用、参数匹配、FPR、FNR、忠实度 |

所有效果结论都应区分工程测试、模型离线评测、小样本用户试用和正式教学效果。项目不会仅凭一次演示或少量用户反馈宣称成绩显著提升。

## 十二、风险与伦理边界

| 风险 | 控制措施 |
|---|---|
| 模型幻觉与错误引用 | 使用来源登记、RAG 证据和待补来源标记；禁止把无证据内容写成事实 |
| AI 错误评分 | AI 结果仅作建议，教师复核并主动发布后才进入正式反馈 |
| 学生数据越权 | 角色、班级成员关系和资源作用域校验；教师只读本班正式教学证据 |
| 科研数据与结论被滥用 | 项目级隔离、动作审批、版本记录、方法说明，不生成虚构数据或结论 |
| 简单演示账号暴露 | 仅使用无真实数据的临时账号，演示结束立即停用或修改密码 |
| GPU 与外部服务不可用 | 区分离线功能与模型功能，支持明确失败和有限降级，不伪造成功结果 |
| 小样本效果被夸大 | 明确样本规模和验证边界，不将短期试用等同于正式教学成效 |

## 十三、立项结论

星知智链选择计算机学科中可验证、可形成闭环的真实任务作为切入点，以学生个性化学习、教师班级诊断和科研流程辅助为三条应用主线。项目的核心价值不在于增加一个聊天入口，而在于建立一套能够把学科知识、真实任务、学习证据、教师判断和科研材料连接起来的可信基础设施。

项目已有较完整的技术原型和工程验证基础，具备正式立项并进入目标环境联调与用户验证阶段的条件。立项后的关键不是继续无边界增加功能，而是完成 GPU 与外部服务部署、跑通真实教学研任务、形成量化用户证据，并围绕模型误触发、知识来源质量和教学效果持续迭代。
