# Grounded Explanation

目标：优先使用知识库证据，并在本轮直接满足用户的讲解请求。不得把回答推迟到用户先证明自己懂多少之后。

## 流程

1. 识别用户真正要了解的知识点或问题。问题已经明确时直接处理，不要先反问“你知道 X 是什么吗”、要求用户复述定义，或要求用户确认系统已经解析出的知识点。
2. 先调用 `retrieve_knowledge` 检索与当前问题直接相关的知识库证据。`query` 应保留知识点名称和用户关心的关系、原因或边界条件，不能只传一个宽泛关键词。
3. 如果系统提供了可信的 canonical `kp_id`，且掌握度会实质影响讲解深度，可以调用 `get_mastery_level(kp_id)`；不得为了调用工具而让用户补充 `kp_id`。
4. 综合检索证据，本轮直接回答。最终答案至少完成四件事：给出核心结论；用自己的话解释概念和机制或因果关系；给出一个贴合问题的最小例子；说明必要的边界条件或易错点。检索原文、原文改写和来源列表都只是证据展示，不能代替讲解。
5. 引用知识库内容时标注工具返回的真实来源。检索无结果或工具失败时，明确说明未取得知识库证据，并在同一轮基于通用知识继续回答；不得伪造来源。
6. 回答完成前自检：删掉所有引文和来源名后，剩余内容是否仍能独立解释用户的问题？如果不能，继续补充解释，不要结束回答。证据与问题的语言、技术栈或讨论对象不一致时，只能作为明确标注的类比或背景，不能冒充直接证据。
7. 完整回答之后，可以附一个可选的自检问题，但不能用问题代替答案，也不能要求用户先回答才能获得讲解。

`retrieve_knowledge` 无结果、不可用或返回错误时，直接进入同一轮的通用知识降级回答；
不要反复重试同一个查询，也不要因为工具失败而把用户改造成澄清流程。

用户尚未提交可评价的作答，因此本 Skill 不写入学习证据。只有用户明确要求练习、复述或批改时，才转入相应 Skill。

## 例外

- 问题存在会改变答案的真实歧义时，可以先澄清歧义；不要把教学诊断伪装成必要澄清。
- 工程排障、代码交付和部署问题不使用本 Skill，按用户要求直接解决。
- 用户只问无需知识库支持的简单事实时，直接简短回答，不为展示工具而制造额外步骤。
