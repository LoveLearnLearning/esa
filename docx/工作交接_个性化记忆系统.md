### Task 2: 掌握度模型 v2

**新增文件：**

| 文件 | 说明 |
|------|------|
| [backend/agent/memories/mastery_store.py](file:///d:/4github/esa/backend/agent/memories/mastery_store.py) | `MasteryStore` 类：掌握度更新 + 衰减 + 优先级 + 复习预测 + 前置追溯 |

**关键 API：**
```python
ms = MasteryStore('data/mastery.db')
ms.record_answer(user_id, kp_id, correct, confidence=1.0)  # 答题更新
ms.get_mastery_level(user_id, kp_id)  # → float (含惰性衰减)
ms.apply_decay(user_id)  # → int (批量固化衰减)
ms.get_priority_ranking(user_id, course, weeks_to_exam, total_weeks, kg_store)  # → list[dict]
ms.get_report(user_id, course, kg_store)  # → dict (avg/weak/strong/stale)
ms.get_review_timing(user_id, kp_id)  # → dict (HLR 半衰期预测)
ms.get_weak_prerequisites(user_id, kp_id, kg_store)  # → list[dict] (BFS 前置追溯)
ms.get_top_weak(user_id, k=3)  # → list[dict]
ms.get_top_strong(user_id, k=3)  # → list[dict]
```

**算法理论依据（详见 [掌握度算法理论依据.md](file:///d:/4github/esa/docx/reference_paper/掌握度算法理论依据.md)）：**

| 算法模块 | 理论基础 | 核心公式 |
|----------|---------|---------|
| 衰减算法 | Ebbinghaus 遗忘曲线 + HLR | `R = exp(-Δ/S)`, `S = 5*(1+2*practice_count)` |
| 答题更新 | Bloom 掌握学习 + BKT | confidence 模拟 P(G)/P(S) |
| 优先级打分 | Desirable Difficulties + 过度练习 | `base + challenge(40-70:+0.15) - penalty(>85&>10:-0.15)` |
| 复习时机 | HLR 半衰期预测 | `days_until = -S*ln(0.7) - days_elapsed` |
| 前置追溯 | ACE 教育知识图谱 | BFS 筛选 mastery < 50 的前置，按 depth 降序 |

**关键设计：惰性衰减 + 定期固化**
- `get_mastery_level`：实时计算指数衰减，不写库
- `apply_decay`：批量固化，更新 `last_decay_at`
- 衰减窗口：`max(last_decay_at, last_practiced_at)` 到 `now`，避免双重衰减

## 三、遇到的问题及解决方案

### 问题 1: 衰减公式方向反了（🔴 严重）

| 项目 | 内容 |
|------|------|
| **问题** | 初版 `decay = 0.02 * days * (mastery/100)` 导致高掌握度衰减**快**（与 Ebbinghaus 理论相反） |
| **发现方式** | 文献调研后发现 Ebbinghaus 遗忘曲线中，掌握越牢固遗忘越**慢**（半衰期越长） |
| **解决方案** | 改为半衰期指数衰减：`stability = 5*(1+2*practice_count)`，`decayed = mastery * exp(-days/stability)` |
| **验证** | 高掌握度(practice=10)衰减 9.1% < 低掌握度(practice=1)衰减 48.7% ✅ |

### 问题 2: get_review_timing days_until 未减已过天数（🔴 严重）

| 项目 | 内容 |
|------|------|
| **问题** | `days_until = -stability * ln(threshold)` 返回总天数，未减去已经过去的天数 |
| **发现方式** | 全面复查时发现验证结果不合理（5天后仍显示"5天后复习"） |
| **解决方案** | 改为 `days_until = max(0, int(total_days - days_elapsed))` |
| **验证** | 刚练→5天、3天后→2天、5天后→0天、30天后→0天 ✅ |

### 问题 3: loader.py 与 rag/document/loader.py 重名

## 四、关键决策依据

### 决策 1: 专注计算机学科（而非数学/计算机/医学三档）

| 项目 | 内容 |
|------|------|
| **原计划** | REQUEST.md 提到"数学/计算机/医学"三档 |
| **决策** | 专注计算机学科 |
| **依据** | (1) 9 所名校培养方案并集已足够丰富；(2) 医学场景信息错误风险高（REQUEST.md 约束 2）；(3) 资源有限，集中精力做好一个学科 |

### 决策 2: Skill 设计为"用户主动触发"而非后台自动

| 项目 | 内容 |
|------|------|
| **原计划** | 推荐练习/掌握度报告/作业批改作为后台自动行为 |
| **决策** | 设计为 Skill，用户主动要求才激活 |
| **依据** | 用户反馈"有些功能是要用户自己选择打开和关闭的skill"；Shafi (2025) 的"受约束的 AI"理念 |

### 决策 3: SQLite 独立表而非图数据库

| 项目 | 内容 |
|------|------|
| **决策** | 知识图谱用 SQLite 独立表 + BFS 遍历，而非 Neo4j |
| **依据** | (1) 与现有数据层一致（CoreMemory 也是 SQLite）；(2) 无额外依赖；(3) 473 知识点的规模 BFS 性能足够 |

### 决策 4: 惰性衰减 + 定期固化

| 项目 | 内容 |
|------|------|
| **决策** | `get_mastery_level` 实时计算衰减不写库，`apply_decay` 批量固化 |
| **依据** | (1) 避免每次查询都写库；(2) `last_decay_at` 字段避免双重衰减；(3) 适合定时任务（如每日凌晨） |

### 决策 5: confidence 参数模拟 BKT 的 P(G)/P(S)

| 项目 | 内容 |
|------|------|
| **决策** | `record_answer` 加 `confidence` 参数（0.0-1.0），低置信度答对增幅打折 |
| **依据** | Corbett & Anderson (1995) 的 BKT 四参数模型；Demo 阶段不需要完整 BKT，但需要区分"蒙对"和"真掌握" |
