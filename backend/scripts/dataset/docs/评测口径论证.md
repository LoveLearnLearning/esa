# 评测口径论证

> 建立：2026-08-19　　对应后端基准 `ce37198`（冻结中）
> 用途：《06—效果验证报告》的方法学一节；同时是判分器改动的依据存档

## 〇、这份文档回答什么

上一轮收工时留了一句判断：

> 在拿到第一张真实评测表之前，整套量具从来没有被真正验证过。
> 下一轮如果还要动评测口径，值得先问一句：**这个指标如果是错的，我怎么会知道？**

这份文档就是那句话的落实。分两件事：

1. **对外**：我们这十几个指标，在公开的工具调用评测里有没有对应物？口径站不站得住？
2. **对内**：把「这个指标如果是错的我怎么会知道」逐项问一遍，问出三处**方法学缺陷**，
   都在 2026-08-19 修掉了，并补了回归测试。

结论先写在前面：**指标的骨架站得住，出问题的是分母、聚合方式和不确定性表述** ——
也就是说，我们一直量对了「量什么」，量错了「怎么算」。

## 一、我们量什么

| 指标 | 分母（题数来源） | 目标 |
|---|---|---|
| 格式合法率 | 全部题 | ≥100% |
| 工具选择准确率 | 应调工具的题 | ≥90% |
| **工具调用完全正确率** | 应调工具的题（工具选对**且**参数填对） | ≥85% |
| 误触发率 FPR | 不该调工具的题 | ≤5% |
| 漏调率 FNR | 应调工具的题 | ≤10% |
| 参数完全匹配率 | 选对工具的题（**条件分母**） | ≥85% |
| 参数 schema 合法率 | 选对工具的题（**条件分母**） | ≥98% |
| 追问命中率 | 全部 ASK_USER 题 | ≥90% |
| 工具失败恢复率 | 全部 RECOVER 题 | ≥90% |
| 结果响应率 | 全部 RESPOND 题 | ≥95% |
| 结果忠实度 | 真答了且观测能抽出实体的题（**条件分母**） | ≥98% |
| 拒绝命中率 | 全部 REFUSE 题 | ≥100% |

分层：**L1 同分布 / L2 状态外推 / L3 场景外推**。
L3 是 `get_review_timing` 一整组留出，训练时一条样本都没给过。

## 二、逐项对照公开基准

| 我们的项 | 公开基准里的对应 | 出处 |
|---|---|---|
| 误触发率 FPR | BFCL **Irrelevance Detection**：给出的函数没有一个相关，模型应当**一个都不调**。BFCL 里这是最大的一个子集（875 条） | [BFCL](https://gorilla.cs.berkeley.edu/leaderboard.html) |
| 漏调率 FNR | BFCL **Relevance Detection**：至少有一个相关，模型应当调；因为正确答案可能有无穷多种，BFCL **只判有没有调、不判调得对不对** —— 和我们把 FNR 与工具选择分开报是同一个理由 | 同上 |
| 工具选择 + 参数 | BFCL **AST accuracy**：不真的执行，比抽象语法树。**漏调直接算错**，分母是题数 | 同上 |
| 工具调用完全正确率 | 就是上面那条 AST accuracy 的直接对应物（2026-08-19 新增，见第三节） | 同上 |
| L1 / L2 / L3 | ToolLLM 的三级泛化：unseen **Inst.**（同样的工具、没见过的说法）→ unseen **Tool** → unseen **Cat.**。我们的 L3 整组留出 `get_review_timing`，正对应 unseen Tool | [ToolLLM (ICLR'24)](https://arxiv.org/abs/2307.16789) |
| 结果忠实度 | RAGAS **Faithfulness** / **FActScore** 那一类「把回答拆成原子事实、逐条回上下文核验」。**我们只核数字**，是它的一个真子集 | [RAGAS](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/faithfulness/) · [FActScore](https://arxiv.org/pdf/2305.14251) |
| 分层必须分开报 | 后端自己的检索评测写着：「对五个阶段分别评分，**不能只报告最终 Reranker 的结果**」 | `backend/agent/rag/evaluation/metrics.py` |
| 宏平均 | 后端同一文件：「按问题计算指标后取宏平均，**避免大文档或多答案问题主导结果**」 | 同上 |
| 负例不得携带 gold | 后端 `EvaluationCase.__post_init__` 强制：unanswerable 的用例不能带任何 gold id。与我们「不调用类不得有 `expected_tools`」同构 | 同上 |
| 小样本区间 | **Wilson score 区间**或贝叶斯可信区间；**明确不要用 CLT，也不要用 bootstrap**（小 n 下 bootstrap 的实际覆盖率显著低于名义值） | [Bowyer et al., ICML 2025 spotlight](https://arxiv.org/abs/2503.01747) |
| 成簇的题 | 同上：题目成簇时，只有考虑聚类结构的模型能给出正确覆盖率；现成的频率派方法没有 | 同上 |
| 同题配对比较 | 两个模型跑同一套题时应做**配对**分析，能利用相关性、区间更窄 | [Miller, 2024](https://arxiv.org/abs/2411.00640) · Bowyer 2025 |

**判断：口径的骨架站得住。**「该不该调 / 调哪个 / 参数对不对 / 不该调时会不会乱调」
这四类正是 BFCL 的核心组成，分层设计与 ToolLLM 的三级泛化同构。
我们额外考的三项（工具失败恢复、结果响应、结果忠实度）在通用基准里没有直接对应物，
但它们量的是「工具返回之后模型说的那句话」——**用户真正看到的那句** ——
在教育场景里这恰恰是最该考的，属于合理的领域扩展，不是自造指标。

## 三、2026-08-19 修掉的三处方法学缺陷

### 3.1 三项指标的分母**随模型行为变化** 🔴

| 指标 | 旧分母 | 后果 |
|---|---|---|
| 工具选择准确率 | 模型**实际调了工具**的题数 | 模型漏调的题从分母里消失 —— 只统计了它有把握的题 |
| 拒绝命中率 | **没调工具**的拒绝题 | 在拒绝题上调工具 = 那道题不见了，而不是记一次失败 |
| 追问命中率 | **没调工具**的追问题 | 同上 |

后果不是精度问题，是**两个模型没在同一道题集上比分**。已公布的表里就有实例
（分子分母由百分比反推，待用 `report_*.json` 的 `_stats` 当场核实）：

```
拒绝命中率  base  66.7% = 4/6
            lora  60.0% = 3/5      ← 分母从 6 掉到 5
```

分母掉一道，说明 **lora 在一道拒绝题上调了工具**。那是比「没说出拒绝措辞」更严重的行为
（赛题《02》的强制承诺项），而旧口径把它读成了「小幅下滑 6.7 个点」。
固定分母之后是 **3/6 = 50.0%** —— 数字更难看，但它说的是真话。

工具选择方向相反，固定分母让**提升幅度更大**：base 漏调多、分母小，
把漏调计为错之后，base 掉得比 lora 多。

**修法**：分母一律固定为「这类题一共有几道」。旧口径保留为三个**附注项**
（`工具选择准确率(已调用)` 等），一是能逐位核对「换判分器有没有改动过旧数字」，
二是「选对工具之后填对参数吗」这类条件问题本身有意义，只是不能拿来比模型。

**新增**：`工具调用完全正确率` = 工具选对**且**参数填对，分母是应调题数 ——
就是 BFCL 的 AST accuracy。加它是因为工具选择和参数匹配分开报会互相掩护：
选对了但参数填错，线上照样是一次失败的调用。

**回归测试**：`test_eval_scoring.py` 新增「只在一道拒绝题上调工具」的假模型，
断言**分母仍是 6、命中数掉到 5**；并断言旧口径的附注项确实会缩到 5
（留着它正是为了让这件事看得见）。

### 3.2 题目严重成簇，而我们报的是微平均 🔴

464 道题只来自 **68 个模板**，各分母的集中度：

| 分母 | 题数 | 模板数 | 最大模板占比 |
|---|---|---|---|
| 应调工具 | 164 | 43 | 9.8% |
| 结果响应 / 忠实度 | 160 | 39 | 10.0% |
| **不调用（FPR 分母）** | **130** | **15** | **67.7%**（`S004__仅提及未要求__nofacts` 88 道） |
| 追问 | 32 | 4 | 46.9% |
| 拒绝 | 6 | 6 | 16.7% |
| 工具失败恢复 | 10 | 10 | 10.0% |

**「误触发率 23.8%」里有三分之二的重量压在一个模板上。** 它答的其实是
「模型在**那一个语境**里会不会乱调工具」，不是一个可推广的比率。
微平均等于按模板大小加权，而模板大小取决于我们当初给那个场景写了几条改写话术 ——
**一个纯粹的数据集编写决定，被读成了模型性质。**

这也直接影响下一轮的扩量决策：如果宏平均远好于微平均，
说明问题集中在 `s004` 那个语境，该补的是**那一族的负样本**；
如果两者接近，说明模型普遍爱调写入类工具，那是另一回事。
**先看这一对数，再决定补什么。**

**修法**：每一项同时报 micro / macro / 模板数。主表仍以 micro 为准
（它答「随机抽一道题会怎样」），macro 并列（它答「换一个场景还成不成立」）。
口径与后端 `rag/evaluation/metrics.py` 的宏平均对齐。

### 3.3 没有任何区间估计 🔴

拒绝命中率分母 6、追问 32（其中 30 道来自 2 个模板）、L2 层 58 ——
全都远低于「几百个数据点」这条线，而报告里 ±6.7 个点的变化正在被当成信号讨论。

加上 95% Wilson 区间之后：

```
拒绝命中率 base   4/6  = 66.7%   CI [30.0, 90.3]   宽 60.3 个点
           lora   3/6  = 50.0%   CI [18.8, 81.2]   宽 62.4 个点
追问命中率 lora  30/32 = 93.8%   CI [79.9, 98.3]   宽 18.4 个点
```

两个拒绝区间几乎完全重叠。**「拒绝命中率退步了」这句话根本不成立** ——
不是「退步了但不显著」，是这个分母下什么都测不出来。

选 Wilson 不选别的有出处：Bowyer 等（ICML 2025）的结论是小 n 下 Wilson 覆盖率良好、
长度合适，而 **CLT 区间和 bootstrap 区间都不可信**（bootstrap 实际覆盖率明显偏低）；
Clopper-Pearson 虽然精确但过于保守、区间白白变宽。

**同时新增配对分析**：base 与 lora 跑的是同一套 464 题，旧 compare 表却把它们当成
两份独立样本在相减。配对之后，两边都对、两边都错的题不携带信息，
证据只剩「一个对一个错」的那 b+c 道题，化简成一次抛硬币检验（McNemar 精确检验）。
这是唯一能回答「**L2 退的 14 个点是真回退还是噪声**」的算法 ——
L2 只有 58 道题，两个独立比例之差的区间宽到什么都说明不了。

⚠️ 实现全部用标准库 `math`（`esa/stats.py`），**不引入 scipy/numpy** ——
超算是共享账号，纪律是不装任何包；这样判分随时能在登录节点上跑，不必申请卡。

### 3.4 补充评测集：给成簇的小分母补厚度

3.2 和 3.3 指出的问题，**光改判分器修不掉** —— 分母只有 6 道题，
再好的区间估计也只能诚实地告诉你「测不出来」。所以同时补了一份
**独立的补充评测集**（`data/eval/eval_supp.jsonl`，44 道题）：

| | 主评测集现状 | 补充集新增 |
|---|---|---|
| REFUSE | 6 题 / 6 模板 | **+16 题 / 16 模板** |
| ASK_USER | 32 题 / 4 模板 | **+12 题 / 12 模板** |
| 误触发（hard_negative） | 92 题 / 5 模板（88 题挤在一个模板） | **+16 题 / 16 模板** |

**补的是互不相同的场景，一条一个模板** —— 补同一模板的改写只会让簇更大，
一点也不会让指标更可信。这一条做成了断言（模板数必须等于条数）。

#### 三条隔离保证（都做成了测试，且都反向验过）

补充集**不进训练集、不进主评测集、不改主评测集的抽样**。第三条最要紧也最容易漏：
`evalset.build()` 挑评测模板用「按类别配额 + `rng.shuffle(pool)`」，
而 `random.shuffle` 消耗的随机数与 `len(pool)` 成正比 ——
**补充样本只要参与建 pool，后面所有类别抽到的模板都会跟着变**，
那 464 道题就换了一套，而「这张表只能和作业 77999 那版基线比」是硬约束。
所以补充样本在 `build()` 的**第一行**就被摘走，早于 `by_tpl`、早于任何 shuffle。

验收不是看 sha256 有没有变，而是：**把补充样本全部拿掉再 build 一次，
主评测集与训练集的 id 序列必须逐个相同**。实测两份产物逐字节未变
（`eval.jsonl` = `f95e0c72…`，`train_ir.jsonl` 同）。

反向测试（这一步不做，造出来的就是个永远绿的仪表盘）：

| 故意注入的错误 | 三条检查的反应 |
|---|---|
| 前缀常量改成认不出补充集 | 三条全红 |
| **摘得太晚**（让补充样本参与建 pool，最后再过滤掉） | 第三条红 —— 正是那个「不会有任何东西报错」的失败模式 |

⚠️ 反向测试还查出了**测试自己的**一个毛病：第一版直接 import 了
`evalset.is_supplement` 当判据，于是前缀一改，测试跟着 bug 一起变 ——
「拿掉补充样本」拿掉的是空集，两次 build 当然相同，检查**空跑成功**。
现在测试里写死 `"supp__"`。**测试和被测代码共用判据，等于让被告自己当证人。**

#### 判分侧

两套评测集的 `eval` / `pred` / `report` 文件名**全都不同**
（`--suite main` / `--suite supp`）。共用文件名的话，一次「跑一下补充集看看」
就能覆盖掉主表那份三次作废、两天机时换来的基线产物，而且不会有任何东西报错。

补充集**单独出一张表**，不并进主表，也不拿它讲「微调带来了多少提升」——
它是另一把尺子。`compare` 在 `--suite supp` 下会把这句话直接印出来。

## 四、已知局限（写进《06》，不粉饰）

1. **单步评测 + 黄金前缀（teacher forcing）**。我们把黄金对话前缀连同**真实工具观测**
   喂给模型，只判它的下一步。真实部署是多步 rollout，误差会沿轨迹累乘 ——
   一个每步 95% 的 Agent 走八步只剩约 66%。
   **所以这些数字是单步能力的度量，不能读成端到端任务成功率。**
   BFCL v3 的多轮状态化评测与 τ-bench 的多轮 rollout 正是为补这一层。
2. **`temperature=0` 单次采样**，没有 τ-bench 那种 `pass^k` 可靠性度量 ——
   我们量的是「一次会怎样」，不是「重复八次还稳不稳」。
3. **拒绝/追问用关键词判据**（`validate.py` 的 `_REFUSE_MARKERS` / `_ASK_MARKERS`）。
   文献对字符串匹配的拒绝判据两头都有批评：既漏（词表覆盖不全模型的各种拒绝说法），
   又误（「很抱歉听到你…」被当成拒绝）。我们的词表是从 19 条真实回答里逐条长出来的、
   且只判**言语行为**（有没有表明不做），比通用词表稳。

   🔴 **但这一轮撞到了实证。** 写补充评测集时手写了 26 条参考回答
   （14 条拒绝 + 12 条追问），全部是合格的中文，`validate` 当场判回来两条：

   | 被判不合格的回答 | 判据为什么没认出 |
   |---|---|
   | 「式子没跟过来。**请把要算的表达式发我**。」 | `_ASK_MARKERS` 里有「请告诉我」「请提供」，没有「请把…发我」 |
   | 「带姓名和身份证号的数据**我不碰**。」 | `_REFUSE_MARKERS` 里有「不做」「不处理」，没有「不碰」 |

   **26 条里漏了 2 条 ≈ 8% 的假阴性**，而且这是**人写的、刻意求合格**的回答。
   模型自由生成时用词更散，漏检率只会更高 ——
   也就是说**追问命中率与拒绝命中率大概率是被低估的**，
   而这两项恰好一个是赛题《02》的强制承诺项、一个分母只有 6。

   这一轮**没有**动词表，理由是：改判据会改主表的数字，而在没测过判据本身的
   准确率之前就扩词表，等于用一个没验证过的量具替换另一个 ——
   这个项目已经栽过十几次。正确顺序是**先测一致率再改**：
   拿 base/lora 在那 38 道题上的真实回答逐条人工标一遍，
   算出判据的假阴性/假阳性，再决定扩到哪里。⬜ 下一轮做，见第五节。
4. **结果忠实度只核数字**，不核事实性陈述；`掌握得不错（80%+）` 这类**约数**仍会被判编造。
   配对校验挡掉了绝大多数误报（15.1% → 71.5%），剩下这类还在。
5. **判的是文本形态还原**，不是「后端 `parse_output` 读不读得懂模型的原始输出」——
   服务端已把工具调用解析成结构化 `tool_calls`，我们再还原成 qwen 的 JSON 文本形式。
   B3 那件事由 `test_parser_compat.py` 在本地管，两件事别混（超算手册 3.3）。
6. **评测集与训练集同源**：同一批种子、同一套生成器，只按 `template_id` 互斥切分。
   所以 L1 的高分包含「同分布」的成分，**真正的泛化证据是 L2 和 L3**。
   L3 的 16.3% → 94.1% 之所以最有说服力，正是因为那个工具训练时一条都没给过。

## 五、这一轮没做、但值得下一轮做的

| 事 | 为什么值得 | 为什么这一轮不做 |
|---|---|---|
| 拒绝/追问判据的人工一致率 | 局限 3。**已有 8% 的假阴性实证**，而且这两项一个是《02》强制承诺项、一个分母只有 6 | 要拿模型的真实回答来标，得等补充集跑完 |
| 分层贝叶斯（Beta-Binomial）聚类区间 | 比宏平均更严谨，Bowyer 推荐的正解 | 要写重要性采样，收益不及先把宏平均报出来 |
| 多轮 rollout 评测 | 局限 1，才是端到端的真实数字 | 要重做评测框架，9/5 之前来不及 |
| `pass^k` | 局限 2 | 要 k 倍机时 |
| 忠实度扩到事实性陈述 | 局限 4 | 需要 LLM-as-judge，而判官本身又要一轮验证 |
