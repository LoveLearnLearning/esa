## 一、当前阶段结论

项目目前处于 **“核心功能原型已经闭环，工程质量验证已通过，目标环境联调和真实用户验证尚未完成”** 的阶段。

更具体地说：

- 学习、教学和科研三个工作空间均已有前后端实现；
- 学生个性化学习状态、教师作业闭环和科研项目工作流已有代码与自动化测试证据；
- 计算机学科知识图谱、来源对齐知识库、LoRA 数据与固定考卷评测已经形成；
- 当前工作机后端全量测试、Lint、类型检查和材料证据核验全部通过；
- 公网 Flutter 静态页面可以访问，但 2026 年 9 月 10 日 `/api/health` 返回 HTTP 502；结合当前机器没有可用 GPU 的实际情况，后端模型与完整在线流程暂时无法运行；
- 正式立项所需的技术路线已经具备，下一阶段重点应从“继续堆功能”转向“目标环境恢复、端到端验收、用户试用和效果量化”。

因此，项目不是停留在概念或界面阶段，但也尚不能表述为已经完成正式部署、规模化教学应用或科研生产验收。

## 三、已完成的核心能力

### 3.1 学生侧：个性化学习闭环

当前代码已经实现以下能力：

1. **课程与知识地图。** 学生可以选择课程，查看课程知识点及其前置关系，打开知识点详情并进入学习对话。
2. **学习证据统一写入。** 可评价的练习、作业、回忆、复述和迁移表现通过单一服务写入；未知知识点会被拒绝，幂等键防止重试导致重复计数。
3. **Student Model V2。** 综合正确性、提示级别、尝试次数、独立性、回忆、解释、迁移和证据可靠性更新掌握度；保持率根据时间和稳定性单独计算，不会因时间流逝直接改写长期掌握度。
4. **差异化教学策略。** 根据学习记录选择基础、标准和进阶三档讲解深度；发现薄弱前置知识时，可以先补前置；未知状态不会被误判为薄弱。
5. **学习行动输出。** 已提供掌握度报告、练习推荐、复习队列、薄弱前置查询和知识地图等接口与界面。
6. **作业反馈回流。** 教师发布的正式作业反馈会写入学生学习证据，随后可用于个人讲解与练习推荐。

当前结论：**个性化机制已经从“按偏好换语气”发展为“按真实证据改变教学深度和下一步行动”，但尚缺真实学生的纵向使用数据。**

### 3.2 教师侧：班级管理与作业诊断闭环

当前教师端已经实现：

- 教师角色校验和独立教学空间；
- 创建班级、生成班级码、按用户名邀请学生；
- 学生接受或拒绝邀请、通过班级码加入；
- 创建包含 1–30 道简答题或代码文本题的作业；
- 设置题目满分、评分标准、参考答案和知识点标签；
- 发布作业并查看学生提交情况；
- 对单份或整份作业运行 AI 结构化分析；
- 教师逐题修改分数、错因、评语和知识点；
- 必须完成全部题目复核后发布正式反馈；
- 学生在发布前看不到 AI 分数、评分标准和参考答案；
- 班级看板按已发布反馈聚合知识点得分率、薄弱人数、关注学生和可能的前置根因；
- 教师只能访问本人班级，学生只能访问本人的作业、提交与已发布反馈；
- 邀请、提交、分析、复核、发布和学生详情访问具备审计记录。

自动化集成测试已覆盖“教师建班—邀请—学生接受—发布作业—学生提交—AI 分析—教师复核—发布反馈—班级看板—成员移除后的历史访问边界”完整纵向流程。

当前运行数据库中已有 1 个内测班级、1 条成员关系、1 份已发布作业和 1 份已发布反馈的历史开发记录。2026 年 9 月 10 日又创建了 `teacher_demo` 与 `student_demo` 两个无真实身份数据的临时账号，但尚未为这两个新账号建立演示班级、课程、作业和提交关系。

当前结论：**教师端的业务闭环已经实现，下一步主要是准备干净演示数据并在真实模型环境中完成一次完整预演。**

### 3.3 科研侧：项目化科研流程辅助

科研空间当前已实现以下核心对象和流程：

1. **科研项目。** 用户可创建、修改和归档项目，并配置项目级说明与智能体指令。
2. **前沿追踪。** 系统同时获取按时间和相关性排序的 arXiv 结果，完成去重、时间窗过滤、年度分布、类别统计、热点词和增长信号分析，并明确这些结果只属于筛查信号，不是计量学证明。
3. **研究文档。** 支持大纲、文献综述、论文和笔记等文档类型，更新时保留历史版本。
4. **科研写作任务。** 支持大纲生成、文献综述、润色和格式检查；系统提示词要求只使用已有材料，缺少证据时标记 `[待补来源]`，禁止虚构作者、年份、题名、DOI、数据和实验结果。
5. **科研数据。** 支持上传不超过 15 MB 的 CSV、JSON 和 TXT 数据，生成行列、缺失值、唯一值和数值分布概览。
6. **数据分析。** 已实现描述统计、Pearson 相关、分组比较和文本频次分析；输出包含方法边界，例如明确说明相关关系不建立因果关系。
7. **项目级授权。** 前沿、写作和数据分析任务在启动和执行前检查项目、文档和数据集是否仍属于当前用户及当前绑定项目。

当前运行数据库中存在开发阶段科研项目和一份版本化文档记录，但尚无已上传科研数据集。数据分析能力已通过自动化测试，不等于已经完成真实科研数据验证。

当前结论：**科研空间已经覆盖“找资料—组织材料—辅助写作—分析数据”的基本链路，但真实外部检索、模型写作质量和领域数据分析仍需在目标环境和真实项目中验收。**

### 3.4 教学研贯通现状

目前已经完成的直接贯通是教学与学习：

```text
教师任务和知识点标签
→ 学生真实提交
→ AI 建议与教师复核
→ 正式反馈和学习证据
→ 个性化学习策略
→ 班级共性诊断
```

科研空间已经与学习、教学空间共享身份体系、Agent Runtime、知识来源规范和权限治理框架，但“科研成果经审核后进入课程知识库”的自动化发布流程尚未实现。当前采用人工确认和来源登记，避免未经核验的研究生成内容直接影响课程教学。

因此，当前应表述为：**教学与学习已形成业务闭环，科研已形成独立项目闭环，三者已在统一平台和治理框架下集成；教学与科研之间的内容发布闭环仍处于下一阶段。**

### 5.1 已形成的训练资产

- 主考卷指纹：`d441611fb5556b53#440`。

### 5.2 定版 LoRA 的可核验结果

定版适配器在同一 440 道考卷、同一判分器和 `temperature=0` 条件下，与基座模型逐题配对：

| 指标 | 基座模型 | 定版 LoRA | 判断 |
|---|---:|---:|---|
| 工具选择准确率 | 35.5% | 81.1% | 显著提升 |
| 工具调用完全正确率 | 26.0% | 69.8% | 显著提升 |
| 参数完全匹配率 | 73.3% | 86.1% | 显著提升 |
| 漏调率 FNR | 53.8% | 5.3% | 显著改善 |
| 结果忠实度 | 53.8% | 99.4% | 显著提升 |
| 误触发率 FPR | 0.0% | 30.5% | 显著退化，尚未解决 |

基座模型的低误触发来自整体过度保守，同时存在 53.8% 的漏调；LoRA 大幅降低漏调，却提高了误触发。这一真实权衡已经被记录，而不是只选择有利指标。

项目已离线验证推理期工具调用闸门，可将 FPR 从 30.5% 降至 8.5%，但仍高于不超过 5% 的目标，且该闸门尚未接入默认推理链路。因此，当前不能表述为误触发问题已经解决。

### 5.3 Agent Runtime 已实现能力

当前 Tool Schema 快照包含 31 项能力，覆盖数学与位运算、Web/arXiv 检索、知识库、学习状态、附件解析、沙箱以及三类科研动作。运行时不是把所有能力同时交给模型，而是根据工作空间、会话模式和资源授权编译当轮可用工具。

已实现的控制包括：

- 学习、教学、科研空间使用不同 Skill 和 Tool 范围；
- 未绑定科研项目时不暴露科研工作流；
- 未授权附件不能被解析；
- `isolated` 和 `no_write` 会话限制记忆读写；
- 工具参数按 Schema 检查未知字段和必填字段；
- 科研动作支持“提出—审批—执行”流程；
- 模型内容、用户展示内容和内部审计信息相互分离。

## 八、当前未完成事项与风险

### P0：阻塞演示和验收

1. **GPU 与后端服务未恢复。** 当前公网 API 为 502，无法进行真实在线演示。
2. **主辅模型未在目标环境验收。** 需要确认 Qwen3.5 主模型、LoRA、辅助模型、vLLM 地址和显存配置。
3. **双账号教学闭环未在目标环境跑通。** 数据库和代码验证不能替代浏览器真实操作。

### P1：影响可信性和正式立项验证

1. **RAG、Qdrant、MinerU 尚未现场验收。** 当前 RAG 默认关闭，内容可追溯能力缺少目标环境截图和结果记录。
2. **真实用户验证尚未完成。** 尚缺至少 1 名教师或教学协助者、1 名学生的结构化试用记录。
3. **三个典型问题尚未在当前版本重新运行。** 需要保存原始输入、输出、来源、时间和人工判定。
4. **科研真实案例不足。** 当前数据分析只有自动化测试证据，运行数据库没有真实演示数据集。
5. **工具误触发仍偏高。** 闸门从 30.5% 降到 8.5% 仍未达到目标，且尚未进入默认路径。

### P2：影响后续规模化

1. 当前教学题型主要是简答题和代码文本题，尚未覆盖复杂编程运行评分、公式过程题和多模态作业。
2. 班级看板是实时聚合，小规模可用，大班级仍需缓存、预计算与性能测试。
3. 当前没有独立助教组织权限、多教师协作、完整通知和预警处置闭环。
4. 科研数据分析尚缺显著性检验、回归建模、可视化导出和代码/公式可执行验证。
5. 课程资源从科研成果到公共知识库的审核发布流程尚未自动化。
6. 代码沙箱默认关闭，LSP 在当前环境缺少 `clangd`，不能宣称目标环境已可执行任意代码任务。

## 九、下一阶段工作建议

### 第一优先级：恢复可运行系统

1. 获得 GPU 资源并启动主模型、辅助模型和 vLLM 服务；
2. 启动 FastAPI 后端，确认 `/api/health` 从 502 恢复为 200；
3. 验证登录、SSE、模型响应、超时与错误提示；
4. 启动 Qdrant、Embedding 和 MinerU，完成一份真实资料的解析、索引、检索和引用展示。

### 第二优先级：完成端到端 Demo 数据

1. 使用 `teacher_demo` 创建计算机学科演示班级；
2. 将 `student_demo` 加入班级；
3. 从现有知识图谱选择真实课程和知识点；
4. 创建 1 份简答或代码文本诊断作业；
5. 完成提交、AI 分析、教师修改、正式发布和学生刷新；
6. 检查班级看板、个人掌握度和学习助手是否同步变化；
7. 清除无关通知、旧缓存和敏感数据后进行录制预演。

### 第三优先级：形成可提交的效果证据

1. 邀请至少 2 名真实目标用户完成结构化试用；
2. 记录教师处理时间、AI 建议修改率、学生反馈可理解性和下一次任务表现；
3. 运行 3 个典型计算机学科问题，并与标准答案或权威来源逐项比较；
4. 选择一个科研数据集完成分析，与人工结果进行一致性核验；
5. 将所有结论按“自动化测试、离线模型评测、用户试用、正式效果”分级归档。

### 第四优先级：围绕研究问题迭代

1. 将工具调用闸门或替代方案接入受控实验路径；
2. 增补误触发负样本并保持主考卷冻结，避免为分数修改测试集；
3. 扩充教师侧任务质量与时间指标；
4. 设计科研成果进入课程资源前的来源登记和人工审核流程；
5. 在明确样本量和研究设计后开展课程小规模试点。

## 十、需要指导教师确认的立项事项

1. 是否认可项目以“可信证据驱动的计算机学科教学研闭环”为主线，而不是继续扩展为泛学科聊天平台；

5. 是否同意把教师处理时间、AI 建议修改率、知识点诊断准确性和学生后续独立表现作为主要评价指标；

## 十一、结论

截至 2026 年 9 月 10 日，星知智链已经完成从产品概念到核心功能原型的主要建设：学生侧具备证据驱动的个性化学习，教师侧具备完整的作业与班级诊断链路，科研侧具备项目化的前沿、写作与数据分析能力，底层具备知识图谱、RAG 结构、受控 Agent Runtime、LoRA 训练和系统化评测。

项目当前最主要的问题不是核心代码缺失，而是目标运行资源和效果证据不足。公网静态页面可以访问，但后端因无 GPU 暂时不可用；真实 RAG、模型、SSE 和双账号流程尚未完成现场验收；用户试用和量化效果也尚未形成。因此，项目已经具备正式立项基础，但下一阶段必须以可运行、可复核、可量化为验收标准，完成从“工程原型”到“可验证学科应用”的转换。
